# claude-plugin — repo contract

This repository builds and releases the CloudBackend developer plugin for Claude (`plugins/cloudbackend/`). It is its
own git root under the CloudBackend group, local-only. `README.md` here explains the layout and the scripts; the
plugin's own `README.md` is what users read.

## Rules

- **Never edit `plugins/cloudbackend/skills/` or `SKILLS.json` by hand.** They are generated by
  `node scripts/sync-skills.mjs` from the documentation hub's built skills (`public/public/skills/index.json` and the
  `.skill` zips next to it, checked out at `../estate-docs` or `CBE_DOCS_HUB`). A fix to a skill is made in the hub's
  skill sources, rebuilt there, then synced here. `node scripts/sync-skills.mjs --check` tells you when the copy drifted.
- **The hub's built outputs only.** This repo reads the hub's `public/public/skills/`, `<corpus>/toc.json`, the guard
  module `public/scripts/extension/guard.mjs` with its `_tools/publication-guard.json`, and `_vocabulary/terms.json`.
  It writes the hub's `public/plugin.json` and `_reports/plugin/`. Nothing under the hub's `_source/` or `_skills/`,
  and no other project in the workspace, is ever read by a script here.
- **Commit here, never push.** There is no remote; where the public remote goes (GitHub, GitLab, none) is an open
  decision. `git push` has nowhere to go and must stay that way until that decision is written down.
- **Archive, never delete.** Superseded files move to `_archive/<date>-<what>/` with an `ARCHIVED.md`. Generated
  trees (`skills/`, `clients/`, `dist/`) are regenerated, not archived.
- **`clients/`, the README install block and skills table, `dist/`, and the hub's `public/plugin.json` are generated**
  by `node scripts/gen-clients.mjs`. Edit the generator, not the output.
- **The version is pinned** in `plugins/cloudbackend/.claude-plugin/plugin.json` (`YYYY.MDD.N`) and bumped only by
  `node scripts/bump-version.mjs`, which moves it only when `plugins/` differs from the last release tag `v<version>`.
- **`node scripts/guard.mjs` must report 0 problems** before any commit that touches `plugins/` or `clients/`: no
  workspace paths, no test-tenant hosts outside the skills, and XIOS/3 spelled that way in our own text.
- **The deploy connector stays out of `.mcp.json`.** It is per tenant (`https://mcp.cloudbackend.com/mcp/<tenant>`);
  `plugins/cloudbackend/scripts/connect-deploy.sh` adds it.
- **Product names:** XIOS/3, always with the slash and the digit (the guard refuses the shortened spellings), XVM is
  the XML Virtual Machine, the product is CloudBackend PaaS, CBE is CloudBackend.
- Releases run `scripts/release.sh` by hand, on big, after review (`--dry-run` first). Stages that need the host
  print a hand-off instead of failing. Each release adds a row to `RELEASES.md`.
